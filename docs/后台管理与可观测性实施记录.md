# 后台管理与可观测性实施记录

## 1. 仓库现状与规格差异

现有项目是一个 FastAPI RAG 服务，解析、分块、MySQL 主数据、Qdrant 检索、重排、上下文压缩和 Qwen 回答已经存在。原有接口为 `/api/v1/health`、`/api/v1/chat/query`、`/api/v1/retrieval/debug` 和证据查询接口。数据库迁移已经覆盖药品、文档版本、解析结构、表格、图片、Chunk 和索引状态。

规格要求的管理域、规则发布、解析审计、QA 审计、服务间认证、Trace 和 Prometheus 之前没有实现。当前增量实现保留 RAG 路径，并增加了：独立管理 FastAPI、规则草稿/回归/发布/激活、规则快照缓存、解析审计表、QA 审计表、内部只读接口、任务状态接口、Prometheus 文本指标和可选 Langfuse 批量上报。

## 2. 分阶段计划和当前进度

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| A | 迁移、权限边界、服务间 Token、审计数据模型 | 已完成初版 |
| B | 管理服务、规则草稿/测试/发布/回滚、静态管理页 | 已完成可运行 MVP |
| C | 解析报告按页、bbox、元素、Chunk、异常和复核问题接口 | 已完成数据落库与读取接口 |
| D | QA 审计、指标、Trace、监控失败隔离 | 已完成骨架，需接生产平台验收 |
| E | Worker、PDF.js 原文复核页、PostgreSQL 管理库、OTel Collector | 二阶段 |

规则发布要求经过回归测试；影响索引的版本必须带 `index_version` 才能激活。RAG 实例通过 `RuleSnapshotCache` 把管理域快照原子写入本地文件，查询侧可以在启动或定时刷新时读取。

## 3. 运行方式

```powershell
# RAG：先从 config.example.yaml 复制 config.yaml，填写 mysql_url、rag_internal_token
Copy-Item config.example.yaml config.yaml
.\.venv\Scripts\python.exe -m uvicorn app.web.api:app --reload --port 8000

# 管理服务在相邻的 medical-knowledge-admin 项目中运行，
# 其 config.yaml 的 rag_internal_token 必须与 RAG 项目一致。
```

管理页：`http://127.0.0.1:8001/`。输入 `ADMIN_TOKEN` 后可以创建规则、执行回归测试、发布和激活版本，并查看 RAG 文档、解析页和 QA 审计。管理服务也可直接使用 `uvicorn app.admin.api:app --port 8001` 启动。

## 4. 关键接口演示

```powershell
curl http://127.0.0.1:8001/health
curl -H "Authorization: Bearer admin-dev" http://127.0.0.1:8001/admin/api/v1/intents
curl -H "X-Service-Token: rag-internal-dev" http://127.0.0.1:8000/internal/v1/config-status
curl http://127.0.0.1:8000/metrics
```

非流式问答在配置 `QA_AUDIT_ENABLED=1` 且数据库可写时先写入 `qa_audit`，成功响应带 `answer_id`、`request_id` 和 `trace_id`。审计失败且 `QA_AUDIT_REQUIRED=1` 时返回受控错误，不会声称已经完成审计。Trace 上报失败只计入 `telemetry_export_failures_total`，不会阻断问答。

## 5. 当前限制和二阶段工作

* 管理域默认使用 SQLite 以便本地独立运行，生产应替换为 PostgreSQL 适配器并接入组织用户、密码或 SSO。
* 解析重处理接口目前提交进程内任务并返回状态，尚未接入 Celery/Redis Worker；只在实际需要承载大文件时引入队列。
* Trace 目前提供 Langfuse HTTP 批量导出骨架，二阶段接入标准 OpenTelemetry SDK/Collector，并补齐每个检索阶段的 span 属性。
* 管理页是无构建依赖的静态 MVP，二阶段用 PDF.js 展示原 PDF、bbox、章节和表格叠加，并完成复核操作闭环。
* 规则快照缓存已具备原子写入和哈希校验，下一步把已发布规则版本接入在线 `parse_query`，同时在索引状态中校验规则版本。
* 需要在真实 MySQL、Qdrant、Langfuse 和 Prometheus 环境完成端到端验收，并补充失败重试、告警和保留周期策略。
